24 个环节各自干什么

AppWindow

翻译 + 消费策略

把 DOM 事件包成 engine Event；顺带 preventDefault（消费浏览器默认滚动/缩放）。这是 DOM 的唯一接触层。

Application

接线

构造时 window.attach((e) => layerStack.onEvent(e))。唯一知道"事件往哪走"的人。

LayerStack

单通道派送

遍历 B：事件顶→底、handled 即停；遍历 A：每帧 onUpdate(ts) 底→顶全员。

Dispatcher

类型匹配

dispatch(ctor, fn)：是这种类型就调 fn，TS 自动缩窄；fn 返回 true 标 handled。

3handled 怎么截断的

遍历 B 从栈顶开始逐层给 onEvent(e)，任何一个 layer 把 event.handled 设为 true，LayerStack 立刻停止，更底的 layer 这次看不到这个事件。

  1. 1 Application.sink 收到 window 推来的 event，交给 layerStack.onEvent(event)。
  2. 2 从栈顶开始：最顶的 Overlay（如 EventInspector）先看，它只看不认领（observer 从不设 handled）。
  3. 3 没被认领 → 继续往下。某个 Layer 内部 dispatcher 命中 → fn 返回 true → event.handled = true。
  4. 4 LayerStack 下一轮检查到 handled === true，跳出遍历。更底的 layer 这次就看不到这个事件了。
  5. 5 如果没有任何 layer 认领，事件一路被所有人看过一遍（都被读到，没人消费）。

设计意图：输入通常由"最懂它的那层"消费掉，避免被更底的层重复处理。观察者（调试 UI / 日志）叠在最顶但从不 handled——这是 Hazel 调试 overlay 的模式，也是为什么沙箱检查器能看全。

4Layer 是消费者，不是发布者

旧版这个系统有个 EventBus，任何 layer 都能 publish 新事件（"layer 同时是订阅者和发布者"）。bus 退役后这条没了——Hazel 里没有 bus，layer 之间不靠"发事件"通信。

作为消费者

收 LayerStack 推来的 event

在 onEvent 里用 dispatcher 拆类型 → 命中后跑业务逻辑。相机层听到 KeyPressedEvent，把按键状态写进自己的 model。

不做发布者

跨 layer 靠共享状态 / 组合根

需要让别层知道状态变了？在 Application 里把共享对象传进去，或暴露方法由上层编排。没有第二个事件通道可以推给谁。

这是有意取舍：事件流保持单向、可追踪（谁认领了、谁没看到，栈序说了算），代价是 layer 之间的耦合要靠组合显式写出来，而不是靠一个隐形的总线。

5Layer 端的标准 dispatch 写法

这是 packages/engine/src/events/dispatcher.ts 的实际用法，packages/engine/src/layers/layer.ts 落地后沙箱 ExampleLayer 直接照搬：

class MyLayer extends Layer {
  override onEvent(event: Event): void {
    const dispatcher = new EventDispatcher(event)

    dispatcher.dispatch(KeyPressedEvent, (e) => {
      console.log('key', e.code, 'repeat', e.repeatCount)
      return true   // 消费掉，LayerStack 不再往下分发
    })

    dispatcher.dispatch(WindowResizeEvent, (e) => {
      this.relayout(e.width, e.height)
      return false  // 不消费，让更底的 layer 也能看到
    })

    dispatcher.dispatch(MouseButtonPressedEvent, (e) => {
      this.handleClick(e.button)
      return true
    })
  }
}

三个 dispatch 调用彼此独立 —— 第一个返回 true 不会让后面两个跳过，因为 dispatcher 检查的是 event instanceof ctor，不是 event.handled。这种"全部试一遍"的语义让 layer 写起来很线性；截断发生在 LayerStack 的层与层之间，不在 layer 内部的几个 dispatch 之间。
